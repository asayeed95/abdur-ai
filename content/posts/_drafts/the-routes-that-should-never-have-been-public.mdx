Mnemix's root endpoint used to answer `GET /` by listing everything. No token, no session — any unauthenticated caller who asked what the API was got back eleven internal route names: lookup, contacts, bulk, interactions, feedback, governance, enrichment, merge, waitlist, observe, context. Every one of those routes was locked. The map to them was free.

## What broke

The root manifest — the response that describes the API — enumerated every internal and legacy route to any caller. This was not an auth failure. The routes themselves sat behind the public lock, which mnemix's CLAUDE.md freezes at three v1 endpoints. The failure was the manifest disagreeing with the lock: it advertised the full internal surface to anyone who asked.

Route names are reconnaissance. `governance`, `merge`, `enrichment`, `observe` — those words tell a stranger how the platform is assembled and where its working parts live. Nobody needs a broken auth check to start mapping a system when the system hands over the map at the front door. Attack surface is not only what answers. It is what advertises.

Describing the service is the manifest's job. Name, version, description — that metadata stayed, and it should. Listing the internal routes was never part of the job.

## What it cost

Nothing in the record says anyone used it. There is no incident attached to this commit — the fix shipped as an ordinary PR, not an emergency patch, and that is the cheap version of this mistake.

The standing cost was the exposure itself: for as long as that manifest shipped, every unauthenticated `GET /` returned the full internal route list. I cannot price that in damage because none is recorded. So price the engineering instead: one PR, two commits, one verification run. The expensive version of this story is the one you find out about from someone else's logs.

## The receipts

- Commit `917c80a`, merged to main on 2026-07-12: `fix(api): lock root manifest to public-only routes (#363)`.
- The commit message states the failure directly: "GET / previously enumerated every internal/legacy route (lookup, contacts, bulk, interactions, feedback, governance, enrichment, merge, waitlist, observe, context) to any unauthenticated caller."
- Verification on the PR: `tsc --noEmit` clean; unit suite 502 passed / 1 skipped across 85 files.
- A second commit on the same PR deduped the comment header — the old "Root — API info" block had survived next to the new explanatory comment. One header, not two.

## The pattern

P-021: the manifest is part of the attack surface.

I audited the routes. I did not audit the response that lists them. The set of strings a public endpoint emits is part of the public contract, and it deserves the same scrutiny as the handlers it describes. The prescription: if a route is not public, its name does not belong in a public response. Treat self-describing endpoints — root manifests, generated API docs, verbose health payloads — as disclosure surfaces, and gate their contents, not just their availability.

The PR's verification was `tsc --noEmit` clean and 502 passing unit tests. That proves the trimmed API still behaves. It says nothing about what the manifest had been saying before, because no type checker and no unit test runs the disclosure gate for you. Same shape as P-013 — local-green is not deploy-green — one layer over: a green gate only covers what the gate checks.

## The fix

The PR trimmed the manifest to the public contract: the three frozen v1 endpoints from the CLAUDE.md lock, plus `/health` and `/mcp`. Name, version, and description stayed — non-route metadata is what a manifest is for. Every internal route name came out. The follow-up commit collapsed the doubled comment header, so the file says one thing, once.

The fix is small. The discipline is checking what your public endpoints say, not just what they do.

The routes were locked the whole time; the leak was the list.
