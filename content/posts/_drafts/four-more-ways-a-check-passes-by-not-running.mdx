**Short answer:** a check that cannot do its job still has to end somehow, and the easiest way to end is exit 0, which every caller reads as green. Give "I could not look" a result of its own, different from "I looked and found nothing", and make the check count what exists before it filters anything. Then break its input on purpose and read the result against what you documented. Four checks in Northsun's repository went green without running, for four different reasons. Each is reproduced below in a few lines of Node, with the fix their records describe.

**Status of what this describes:** tooling and test code in Northsun's private repository, merged between August and 2 October 2026. None of it is served code, so none of it is deployed to anything a user touches. Nothing here is a claim about product behaviour, and nothing says which hosts run which hooks or sweeps or that any host is protected. The script in this post is a stand-in with toy checks of its own, described below.

**Who did the work:** not me, as far as I can show. The commits on these changes carry my git name together with an AI co-author trailer. The decision records carry no provenance line and speak in the first person, so I quote their sentences as the records' own and do not claim them, and I do not say which sentence was written by whom. The review findings the records credit came from automated reviewers. The script and the runs of it in this post were done on 7 October 2026 by the AI session that drafts these write-ups, not by me and not by the people or agents who wrote the checks. Where this post says "Northsun", it means that project and its agents.

**Terms, as this post uses them.** An *exit code* is the number a program returns when it ends, and a CI gate treats 0 as green. An *entry-point guard* is the test a script runs to decide whether it was started directly, so that importing it does not run its work. To *fail closed* is to treat a failure to check as a failure. A *denominator check* compares how many things a check classified with how many there were.

## What happened

Northsun is the memory and enrichment layer for AI agents.

Northsun's repository is full of checks written as small scripts: gates that exit 0 for green, a sweep that looks for red workflows, evaluation gates with ceilings. The site has already told several stories about checks that pass without checking. A skipped job satisfied a required check, and a shell operator-precedence slip made a mutation test lie, in [how 29 review rounds hardened a CI gate that nothing ran](/writing/29-review-rounds-hardened-a-ci-gate-that-nothing-ran). Optional chaining on a missing provider made an analytics call that could not fail in [the analytics call that couldn't fail](/writing/the-analytics-call-that-couldnt-fail). A test that counted the wrong thing and read zero for its own burst is in [a load test that counted its neighbours](/writing/load-test-that-never-saw-its-own-burst). These four are different mechanisms, and the repository's records describe each one.

## One: an entry-point guard that never matches

The header of the repository's entry-point helper dates the incident to August 2026. Many scripts had hand-rolled the same guard, comparing `import.meta.url` with the path Node was started with. Node resolves a module entry point through symlinks, so `import.meta.url` holds the real path, while `process.argv[1]` keeps the path as it was typed. On macOS, `/tmp` is a symlink to `/private/tmp`, so any script run from a path under `/tmp` compared unequal. Its main function never ran, the module fell off the end, and the process exited 0. A phase gate that treats exit 0 as green reported clean without validating anything from a worktree under `/tmp`.

The fix, per the header, is to resolve both sides through `realpath` before comparing, and to fall back to the unresolved path instead of throwing when a path cannot be read. The header also cautions that resolving only one side brings the bug back under Node's `--preserve-symlinks-main` flag. That caution is the record's, and the repro below does not run it.

Section 1 of the script reproduces the shape with a check that exits 1 when it finds a problem, run by its real path and through a symlinked directory.

## Two: a gate that stops gating when its ceiling is missing

An evaluation gate asserted that a measured latency stayed under a ceiling read from a budgets file. The run could be pointed at another budgets file, and a legacy one carried keys for a different percentile. The key the gate looked for was then `undefined`, and `measured > undefined` is false for every measured value, so all four latency gates silently stopped gating. The comment in the code puts it plainly: a gate that quietly stops gating is worse than no gate. The decision record says the problem was found in review of the pull request and calls it a real fail-open that the change itself had shipped.

The fix makes a missing ceiling a breach with the message that it is refusing to run ungated. Section 2 of the script shows a gate with and without the fix against a budgets object that lacks the key.

## Three: a monitor that cannot tell blind from clean

The sweep is a script used to decide whether any gate is red. Review found that it could not tell total blindness from a clean sweep. It ran with `set -uo pipefail` and no errexit, so a failed API call still created an empty file. The script then counted zero things, classified zero things, and passed its denominator check because zero equals zero. Nothing was red, so it printed `(no RED, no UNKNOWN)` and exited 0. The record demonstrates it by pointing the script's API client at `/usr/bin/false`. Before the fix: that line and exit 0. After: a verdict that the sweep could not read what it classifies, and exit 2.

Fixing that exposed a second problem, in the exit codes. A failed per-workflow read had first been counted as unknown and reported with exit 1, the code that means "I looked at everything and found red", so a caller could not tell a genuinely red gate from a sweep that could not see. Command substitution discards the API call's status, so a separate counter now carries read failures, and exit 2 is returned before exit 1. The script also checks the status of each read and not only the shape of its output, because the API client can print one valid row and then fail, and a check on shape cannot see that. The documented contract is exit 0 for all clear, 1 for "I read everything and found red or unknown", and 2 for "this sweep cannot be trusted", which is never clean.

The record also admits how the demonstration itself nearly slipped: the author's fail-closed demonstration printed `exit=1` and was read as a pass, two screens below a header documenting exit 2 for exactly that case. In its words, having the measurement is not the same as checking it against the spec.

Section 3 of the script has three sweeps over a world where one of three gates is red: one that swallows read failures, one that notices them but reports them with the same code as red, and one that gives them their own.

## Four: a denominator that shrinks with the numerator, and an absence read as intent

The same sweep filtered out workflows that were not active before it computed its total. The denominator check then compared two numbers that had been reduced in the same way, and it passed while a gate sat disabled and unable to run. Review found it, and the fix is to enumerate every workflow first. A disabled workflow is never green, and a deleted one is counted and reported instead of dropped.

A later change fixed a cousin of the same mistake. The sweep had classified a workflow with zero runs as not applicable, and its header described that state as "PR-only by design". The change's commit message says the script cannot see design: it observed an absence of runs and asserted an intent from it. It added an `ORPHANED` state for a workflow that is active, whose definition path is under the workflows directory but absent from the branch's own listing. The reference set is one read of that listing, tested locally. The check fails closed on a read error and on an empty listing, because an unreadable listing would make every workflow look orphaned, and an empty one contradicts the enumeration that had just returned workflows.

Section 4 of the script counts four gates, one disabled, with the filter before the count and after it, and then reads a zero-run gate as intent and as absence.

## The script

It needs Node 18 or later and nothing else. It makes a scratch directory with a symlink for section 1 and removes it at the end.

```js
// repro.mjs: four ways a check goes green without running. Node 18 or later, no dependencies.
// Run: node repro.mjs
import { spawnSync } from "node:child_process";
import { mkdtempSync, mkdirSync, writeFileSync, symlinkSync, rmSync } from "node:fs";
import { tmpdir } from "node:os";
import { join } from "node:path";

// ---- 1. An entry-point guard that never matches --------------------------------------------------------------
// A check script that only runs its work when it is the entry point. The work "finds a problem", so it exits 1.
const naive = `import { pathToFileURL } from "node:url";
if (import.meta.url === pathToFileURL(process.argv[1]).href) { console.log("check ran: problem found"); process.exit(1); }`;
const fixed = `import { pathToFileURL, fileURLToPath } from "node:url"; import { realpathSync } from "node:fs"; import { resolve } from "node:path";
const real = (p) => { try { return realpathSync(resolve(p)); } catch { return resolve(p); } };
if (real(fileURLToPath(import.meta.url)) === real(process.argv[1])) { console.log("check ran: problem found"); process.exit(1); }`;
const root = mkdtempSync(join(tmpdir(), "guard-"));
mkdirSync(join(root, "real"));
symlinkSync(join(root, "real"), join(root, "alias"), "dir");   // like /tmp being a symlink to /private/tmp on macOS
const exitOf = (file) => spawnSync(process.execPath, [file]).status;
console.log("1. entry-point guard, check exits 1 when it finds a problem (0 would read as green):");
for (const [name, body] of [["naive guard", naive], ["guard that resolves both sides", fixed]]) {
  writeFileSync(join(root, "real", "check.mjs"), body);
  console.log(`   ${name.padEnd(32)} run by its real path: exit ${exitOf(join(root, "real", "check.mjs"))}   run through a symlinked directory: exit ${exitOf(join(root, "alias", "check.mjs"))}`);
}

// ---- 2. A gate that stops gating when its ceiling is missing -------------------------------------------------
console.log("\n2. latency gate, measured value 900 against budgets that may lack the key:");
const gateNaive = (measured, budgets) => (measured > budgets.p95_ms ? "BREACH" : "ok");
const gateClosed = (measured, budgets) => (typeof budgets.p95_ms !== "number" ? "BREACH (ceiling missing, refusing to run ungated)" : measured > budgets.p95_ms ? "BREACH" : "ok");
for (const [label, budgets] of [["budgets with p95_ms: 200", { p95_ms: 200 }], ["legacy budgets with only p99_ms", { p99_ms: 200 }]])
  console.log(`   ${label.padEnd(34)} naive: ${gateNaive(900, budgets).padEnd(7)} fail closed: ${gateClosed(900, budgets)}`);

// ---- 3. A monitor that cannot tell blind from clean ----------------------------------------------------------
// A sweep reads a list of gates, then reads each gate's last result. Exit 0 = all clear, 1 = something is red, 2 = could not look.
const world = (broken) => ({
  list: () => { if (broken === "list") throw new Error("api down"); return ["build", "deploy", "nightly"]; },
  last: (g) => { if (broken === "reads") throw new Error("api down"); return g === "deploy" ? "failure" : "success"; },
});
function sweepBlind(w) {                       // swallows read failures: an empty read looks like an empty world
  let gates = []; try { gates = w.list(); } catch {}
  const results = gates.map((g) => { try { return w.last(g); } catch { return undefined; } }).filter(Boolean);
  const red = results.filter((r) => r === "failure");
  return { exit: red.length ? 1 : 0, text: red.length ? "RED" : "(no RED)" };
}
function sweepOneCode(w) {                     // notices failed reads but reports them with the same code as red
  let gates; try { gates = w.list(); } catch { return { exit: 1, text: "could not read the list" }; }
  let bad = 0; for (const g of gates) { try { if (w.last(g) === "failure") bad++; } catch { bad++; } }
  return { exit: bad ? 1 : 0, text: bad ? "not green" : "all clear" };
}
function sweepHonest(w) {
  let gates; try { gates = w.list(); } catch { return { exit: 2, text: "UNTRUSTED" }; }
  let readFailures = 0, red = 0;
  for (const g of gates) { try { if (w.last(g) === "failure") red++; } catch { readFailures++; } }
  if (readFailures) return { exit: 2, text: "UNTRUSTED" };
  return { exit: red ? 1 : 0, text: red ? "RED" : "all clear" };
}
console.log("\n3. sweep over three gates, one of them red; the API is broken in different ways:");
console.log("   " + "situation".padEnd(27) + "blind".padEnd(19) + "one code for both".padEnd(32) + "honest");
for (const [label, broken] of [["API healthy", null], ["list unreadable", "list"], ["per-gate reads unreadable", "reads"]]) {
  const cell = (r) => `exit ${r.exit} ${r.text}`;
  console.log("   " + label.padEnd(27) + cell(sweepBlind(world(broken))).padEnd(19) + cell(sweepOneCode(world(broken))).padEnd(32) + cell(sweepHonest(world(broken))));
}

// ---- 4. A denominator that shrinks with the numerator --------------------------------------------------------
console.log("\n4. four gates, one of them disabled so it can never run:");
const gates = [{ n: "build", state: "active", last: "success" }, { n: "deploy", state: "active", last: "success" },
               { n: "nightly", state: "disabled", last: undefined }, { n: "lint", state: "active", last: "success" }];
const denominatorNaive = (all) => { const active = all.filter((g) => g.state === "active"); const total = active.length; const classified = active.filter((g) => g.last).length;
  return { exit: total === classified ? 0 : 2, text: `total=${total} classified=${classified}` }; };
const denominatorHonest = (all) => { const total = all.length; const classified = all.length;           // every gate reaches a state
  const notGreen = all.filter((g) => g.state !== "active" || g.last !== "success");
  return { exit: notGreen.length ? 1 : 0, text: `total=${total} classified=${classified} not green: ${notGreen.map((g) => g.n + (g.state !== "active" ? " (" + g.state + ")" : "")).join(", ") || "none"}` }; };
for (const [name, f] of [["filter before counting", denominatorNaive], ["count what exists first", denominatorHonest]]) { const r = f(gates); console.log(`   ${name.padEnd(26)} exit ${r.exit}  ${r.text}`); }
console.log("   and a gate with zero runs, read as intent or as absence:");
const defined = new Set(["build", "deploy", "lint"]);   // the files that exist on the branch
for (const g of [{ n: "lint", runs: 0 }, { n: "ghost", runs: 0 }]) {
  const asIntent = "N/A (PR-only by design)", asAbsence = defined.has(g.n) ? "N/A (definition exists, no runs yet)" : "ORPHANED (active, but its definition is not on the branch)";
  console.log(`   ${g.n.padEnd(6)} naive: ${asIntent.padEnd(26)} checks the definition: ${asAbsence}`);
}
rmSync(root, { recursive: true, force: true });   // the scratch directory this script made for section 1
```

What it shows, with its limits. Section 1: a guard that compares a resolved path with an unresolved one exits 0 through a symlinked directory, and a guard that resolves both sides does not. It does so on Linux with a symlinked directory, and the incident in the record was a macOS `/tmp`. Section 2: a missing key makes an unguarded comparison read as passing, and the guard turns it into a breach. Section 3: only the sweep with its own exit code lets a caller tell a red gate from a sweep that could not look. Section 4: a count taken after the filter passes with a disabled gate in the world, and a count taken before it does not, and a zero-run gate is only suspicious if something checks that its definition exists. It does not show how Northsun's sweep, gate or guard behave today.

## What the four have in common

Each check had a default that meant success. Each could not tell "nothing to report" from "could not see". The fixes the records describe are the same few moves. Make "could not look" a result of its own, with its own exit code, and never let it share a code with "found a problem". Fail closed on a missing input, a failed read and an empty listing. Count what exists before filtering, so the denominator does not shrink with the numerator. Never infer a design from an absence. And demonstrate the fix by breaking the input on purpose.

## What this still does not prove

- The script is not Northsun's code. Its toy checks stand in for the patterns, and its output says nothing about how any Northsun tool behaves today.
- The sweep's own tests are not in the repository this post read, so its behaviour is reported from its header, its commit messages and its decision record, and the pattern is reproduced in a toy and not by running the sweep.
- The repro ran on Linux under two Node versions. The entry-point incident happened on macOS, and the `--preserve-symlinks-main` caution is the record's, not tested here.
- All of it is tooling and test code, merged and not deployed. The post makes no claim about which hosts run which hooks or sweeps, and none that any host is protected.
- The review findings and the demonstrations in the records are as the records report them. They were not re-run for this post, and the repository is private.

## How to check your own checks

Five questions, in order. What does the check exit when it cannot read its input, and is that the same code as when it found nothing? Is the denominator computed from what exists or from what survived a filter? Does "unknown" have a result of its own, separate from red and from clean? Have you run the check through a symlinked path, with a missing config key, and with its API client pointed at a command that always fails, and read each result against what you documented? And is any "by design" label inferred from an absence?

## FAQ

### Why exit 2 and not exit 1 for "could not look"?

Because exit 1 asserts a complete look. The sweep's header says it is never returned when a read failed, so a caller can tell "I read everything and something is red" from "I could not see".

### Why not just turn on errexit?

The sweep's record does not say that would have been enough, and it describes a second problem that errexit would not address: the API client can print one valid row and then fail, so a check on the shape of the output cannot see the failure and only the status can. This post says nothing more about errexit than that.

### Is the symlink problem only a macOS problem?

The incident in the record was on macOS, where `/tmp` is a symlink. The script's section 1 reproduces the same failure on Linux with a symlinked directory, so any setup where scripts are started through a symlinked path can hit it.

### How do I test that a check can fail?

Break its input on purpose and read the result against what the check documents: point its client at a command that always fails, remove a config key, run it through a symlink. The record's own demonstration did the first of these, and the record's own lesson is that printing the result is not the same as comparing it with the specification.
