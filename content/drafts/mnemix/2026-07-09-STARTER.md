## LinkedIn

A client timeout is not a server failure — a lesson our memory substrate taught us the expensive way.

We ran a backfill migration over the table that stores agent memories. It carries a live HNSW vector index, so a full-table UPDATE touches the index on every row. The client hit its timeout and reported failure. The statement kept running on the server — and committed after we'd been told it failed.

Which means "just retry it" is exactly wrong: you'd start the same full-table rewrite a second time, concurrently, on production. The correct check before any retry is pg_stat_activity — is the "failed" statement still alive?

The durable fix was structural: never ship one big mutation. ADD COLUMN in one transaction, the backfill in batches in a second, CREATE INDEX in a third. Each is small enough to observe completing, and a genuine failure leaves an obvious, resumable state.

Building memory for AI agents is mostly this: finding the operations that lie to the operator and redesigning them so they can't.
