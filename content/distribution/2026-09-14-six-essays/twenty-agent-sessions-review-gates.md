## X/Twitter thread

1/ "How do you trust twenty agent sessions with real repos?" I don't. I trust the gates around them. New essay: the five review gates that make it survivable — each one earned by a specific failure.

2/ Gate one: a written operating procedure the session must read first. Two pages, not twenty — short enough that it becomes the session's own voice for the day. "Done" without a command that produced it is banned. In writing.

3/ Gate two: if a rule can be checked mechanically, it must be. My gate script greps staged diffs for changes to locked files and demands a named override. Prose rules decay because the session that breaks them always "has a good reason this time." A grep does not negotiate.

4/ Gate three: the author never approves. Review happens on a different model provider, fresh context, from source — not from the author's summary. Same-model self-review finds what the model was already inclined to miss.

5/ Gate four: claims are typed. Every post declares reported / designed / argued; a "reported" post without receipts fails the build. Twenty sessions generate claims faster than any human can fact-check after the fact — so verification moves into the pipeline.

6/ Gate five: one writer per artifact, and the human holds the irreversibles. Not because my judgment is better — because accountability can't be delegated, so the actions that carry it shouldn't be either. Full essay: https://abdur.ai/writing/twenty-agent-sessions-review-gates
