# RETRO.md — abdur.ai

Lessons a rule could have prevented, one line each, `[source: manual|auto]` tagged. This is the self-evolution log for this repo's (light) build-discipline gate. Unlike the heavier build-discipline package this project pulls from, there is no `EVOLVE.md` generalization pass wired here — that's swarm/multi-project machinery this single content site doesn't need. If entries pile up (5+), read them and decide by hand whether `PROCESS.md` or `scripts/check-phase.sh` needs a change.

- [2026-07-08] This repo got a build-discipline **retrofit**, not a Genesis run — abdur.ai was already ~85% complete with design/content/architecture locked before any of this existed, so Stage 1 (external market research) and Stage 2 (blueprint-from-scratch) don't apply; `CLAUDE.md` and the real code were treated as the source of truth instead. No 7-phase `/spec/*` pipeline, no Decision Contracts, no Engineering Doctrine D1–D13 — this project has no auth, no live payments, no data model to spec yet. [source: manual]
- [2026-07-08] The repo had **zero** ESLint config before this retrofit, which made `npm run lint` / `next lint` block on an interactive setup prompt (`? How would you like to configure ESLint?`) — completely unusable in a pre-commit hook or CI, since there's no TTY to answer it. Added `eslint.config.mjs` (flat config, `next/core-web-vitals` + `next/typescript`) so lint actually runs headlessly. A gate that can't run non-interactively isn't a gate. [source: manual]
- [2026-07-08] Wiring the lint gate immediately surfaced 15 real `react/jsx-no-comment-textnodes` hits — but every one was the locked Clay design system's intentional `///` eyebrow-text convention (e.g. `<p className="eyebrow">/// AITLDR</p>`), not an accidental code comment. ESLint's heuristic can't tell "visible copy that happens to start with `//`" from "a stray JS comment left in JSX." Fixing these by editing the JSX would have violated this repo's own hard rule (don't touch locked copy) to satisfy a *new* gate — exactly backwards. Disabled that one rule with a comment explaining why, instead of touching 15 files of locked content. Lesson for future gates in this or any locked-content repo: a lint/style gate you're introducing for the first time can produce false positives against intentional design conventions — read what it's flagging before "fixing" it, especially in a repo where content is explicitly frozen. [source: manual]

- [2026-09-04] The public-claims gate was **red on the working tree before this session started**, and `build-plan.md`'s C-7 row asserted the opposite ("Static checker, typecheck, lint, production build ... pass"). Three of the six findings were not bad copy at all: `claims_policy.mnemix_context_segments()` windows on Mnemix-bearing *source lines* (`radius=0`, deliberately, so an unrelated timing number elsewhere in a file isn't misread as a Mnemix latency claim) — so when JSX wrapped the sanctioned hedged string `"designed for sub-300ms voice recall"` across two lines, the gate could no longer see it whole and flagged honest, ratified copy. Fixed by reflowing the JSX (zero rendered-output change: within a plain text node JSX collapses newline+indent to a single space), not by widening the policy. Lesson: a gate whose verdict depends on where your source happens to wrap will eventually redden correct work, and a reddening gate is one someone disables. Also: a build-plan row claiming a checker passes is a claim like any other — re-run it, don't read it. [source: agent session]

- [2026-09-04] Converting the palette to `rgb(var(--c-*) / <alpha-value>)` for light mode is a change to every colour on every page, so "dark looks the same" needed to be proven, not eyeballed. The pixel diff alone was **not** sufficient evidence: three pages differed by ~100px each, which turned out to be the `animate-pulse-clay` dot caught at a different phase — an infinite CSS animation makes screenshot equality a flaky test no matter how the capture is timed. The decisive proof was comparing the two compiled stylesheets with the token vars substituted for their dark channel values: 436/436 rules identical. Lesson: when the thing you changed is deterministic (CSS), assert on the deterministic artifact; a screenshot of an animated page can only ever bound the difference, not prove its absence. - [2026-09-04] A "Supabase down" fault test for the W-1 ingest routes was staged by editing `.env.local` and restarting — but `NEXT_PUBLIC_SUPABASE_URL` is **inlined into the server bundle at build time**, so the restarted server kept writing to production Supabase and the test rows ("should not persist") actually persisted. - [2026-09-04] The site shipped analytics call sites (`window.plausible?.(name)`, `window.va?.("event", { name })`) with **no analytics package installed and no provider script loaded** — optional-chaining made every event a silent no-op, so weeks of conversion "tracking" recorded nothing and nothing complained. The *non-conflicting* regions auto-merged from my side and carried three retired-brand lines (`AI proposes. Mnemix governs.`, the sub-300ms line) that main's own brand gate rejects. Rule: after any take-ours/take-theirs resolution, run `git diff <winner> -- <file>`; it must be empty, or every remaining line must be one you meant. Also: a RETRO claim about repo state ("no CI") is a claim like any other and goes stale. [source: agent session]
