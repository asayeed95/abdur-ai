# RETRO.md — abdur.ai

Lessons a rule could have prevented, one line each, `[source: manual|auto]` tagged. This is the self-evolution log for this repo's (light) build-discipline gate. Unlike the heavier build-discipline package this project pulls from, there is no `EVOLVE.md` generalization pass wired here — that's swarm/multi-project machinery this single content site doesn't need. If entries pile up (5+), read them and decide by hand whether `PROCESS.md` or `scripts/check-phase.sh` needs a change.

## entries below this line

- [2026-07-08] This repo got a build-discipline **retrofit**, not a Genesis run — abdur.ai was already ~85% complete with design/content/architecture locked before any of this existed, so Stage 1 (external market research) and Stage 2 (blueprint-from-scratch) don't apply; `CLAUDE.md` and the real code were treated as the source of truth instead. The gate set was scoped light on purpose: build/lint/typecheck + one `[NEVER-SKIP]` grep gate enforcing the existing "don't touch design tokens without an override" rule (turning that prose rule into an enforced check — the classic scar-to-gate). No 7-phase `/spec/*` pipeline, no Decision Contracts, no Engineering Doctrine D1–D13 — this project has no auth, no live payments, no data model to spec yet. [source: manual]
- [2026-07-08] The repo had **zero** ESLint config before this retrofit, which made `npm run lint` / `next lint` block on an interactive setup prompt (`? How would you like to configure ESLint?`) — completely unusable in a pre-commit hook or CI, since there's no TTY to answer it. Added `eslint.config.mjs` (flat config, `next/core-web-vitals` + `next/typescript`) so lint actually runs headlessly. A gate that can't run non-interactively isn't a gate. [source: manual]
- [2026-07-08] Wiring the lint gate immediately surfaced 15 real `react/jsx-no-comment-textnodes` hits — but every one was the locked Clay design system's intentional `///` eyebrow-text convention (e.g. `<p className="eyebrow">/// AITLDR</p>`), not an accidental code comment. ESLint's heuristic can't tell "visible copy that happens to start with `//`" from "a stray JS comment left in JSX." Fixing these by editing the JSX would have violated this repo's own hard rule (don't touch locked copy) to satisfy a *new* gate — exactly backwards. Disabled that one rule with a comment explaining why, instead of touching 15 files of locked content. Lesson for future gates in this or any locked-content repo: a lint/style gate you're introducing for the first time can produce false positives against intentional design conventions — read what it's flagging before "fixing" it, especially in a repo where content is explicitly frozen. [source: manual]
- [2026-07-08] No `.github/workflows` exists in this repo at all — CI-wiring (`bootstrap-ci.sh` in the canonical package) was deliberately skipped rather than inventing a CI pipeline from scratch, which was out of scope for this retrofit. The pre-commit hook is the only enforcement point right now; a push straight to `main` with `--no-verify` bypasses everything. Flagged as an open gap, not silently left out. [source: manual]
- [2026-07-22] The pattern-id namespace (P-008…) had **no registry** — ids were being minted independently in two systems (post frontmatter in this repo; audit records in `mnemix-learning`), and the first cross-system draft batch surfaced it: P-014 means "The typed contract YAML quietly violates" in the launch-postmortem draft but "harden→audit non-termination result" in the mnemix-learning records, and P-009 is defined nowhere in this repo at all. Eight parallel drafters minting ids without a registry would have scaled the collision, not the content. Fix: `content/workflows/mistakes-tldr/FORMAT.md` now carries the canonical pattern-id registry (ranges, claims, contested-id rule), and batches claim contiguous blocks recorded there. Lesson: any id namespace shared across repos needs its registry *before* fan-out, not after. [source: agent session]
