# abdur.ai Design System 1.1

**Owner:** Abdur · **Last updated:** 2026-10-02 · **Version:** 1.1.0 ([CHANGELOG](CHANGELOG.md))

The design system locks what `app/globals.css` and `tailwind.config.ts` already do and invents nothing. Where this folder and the code disagree, the code wins: `node design-system/scripts/build.mjs` fails on any drift.

## The five rules

1. **No hex value anywhere except the token file.** Colours live in `tokens/colors.css` as channel triples and are read as `rgb(var(--c-clay) / <alpha>)`. The build fails on a hex anywhere else under `design-system/`.
2. **Clay is the only accent. Gold is for highlights only**, never buttons.
3. **Playfair Display is for headings only.** Body is Inter (`ss01 cv11 tnum`). Labels, controls, dates and code are JetBrains Mono.
4. **Both themes, always.** Dark is the default and the no-JS fallback. Light is `:root[data-theme="light"]`. Every preview renders both.
5. **No invented numbers, customers or claims in public copy.** The only closer line is *"Choose Northsun as your agent memory layer."*

## Contrast rules (1.1)

Every text pair the site uses holds 4.5:1 in both themes, and the focus ring and input boundaries hold 3:1. These four usage rules keep it that way. `scripts/build.mjs` fails the build if anything in `app/`, `components/` or `lib/` breaks one.

| Do | Never | Why |
| --- | --- | --- |
| Secondary text in `text-meta` | `text-muted`, `text-muted-2`, `text-muted-3` | No muted step reaches 4.5:1 for small text in light (2.58–4.41:1). |
| Success text in `text-good-text` | `text-good` | `good` measures 1.56–1.87:1 on the light grounds. |
| Banded sections and asides on `bg-band` | `bg-bg-2` / `bg-surface-2` under clay or gold text | Light clay on bg-2 measures 4.21:1. `band` is bg-2 in dark and surface in light. |
| Input borders in `border-muted` | `border-border` on a focusable field | A `border` hairline measures 1.14–1.31:1 against its ground. |

Gold text sits only on `surface` (the `.status-near` pill carries its own surface fill). The live matrix is in `tests/contrast.test.html`, and the build writes the same results to `tests/contrast-results.json`.

## Visuals in posts

Diagrams go in a `<Figure>`. Post MDX can use every name below with no import: they're registered once in `components/post/mdx-components.ts`, which `PostArticle` spreads into the MDX renderer.

```mdx
<Figure label="Figure 1" caption="What survives a restart: the log, not the context window.">
<AppendOnlyMemoryDiagram />
</Figure>

<Figure label="Figure 2" caption="Done is a claim until the check's output matches it.">
<VerificationLoopDiagram />
</Figure>
```

| Prop | | |
| --- | --- | --- |
| `caption` | required | One sentence that says what the reader should see. A figure without one throws at render, so `next build` fails. |
| `label` | optional | `"Figure 1"`. Number figures in reading order. Mono, `text-meta`. |
| `size` | optional | `"narrow"` caps the figure at `--aitldr-figure-max` (28rem) for a small visual. The default fills the prose column. |

**Width.** A figure fills the 65ch prose column and never breaks out of it. The site has no breakout layout token, and a wider figure would mean a new layout rule. Diagrams are drawn for the column: a 320-unit-wide viewBox, capped at 440px. That keeps the smallest label near 11px on a 360px phone without the drawing ballooning on desktop.

**Rules**

1. **Caption required**, and the diagram's `<desc>` says in words everything the drawing shows. A screen reader, a feed and a crawler get the whole idea without the picture.
2. **Tokens only.** Colour comes from token classes (`fill-surface`, `stroke-border-2`, `fill-meta`, `stroke-clay` …) or `currentColor`. No hex, no `rgb()` literals, no new colours. Clay is the one accent (the loop or path that matters). Gold stays out of diagrams.
3. **Type roles hold.** Box labels in Inter (`fill-text`), sublabels such as file names and commands in JetBrains Mono (`fill-meta`). Playfair is for headings, so it's not used inside a drawing.
4. **Both themes, and no JS.** Diagrams are server-rendered SVG: no script and no client bundle. They follow the theme through the tokens.
5. **No invented numbers.** A diagram shows a mechanism. It never shows a measurement, a latency, a count or a benchmark the post doesn't already prove with a receipt.
6. **Accessible.** `role="img"` with `<title>` and `<desc>` (via `aria-labelledby`), and nothing interactive inside the SVG.

**Adding a diagram (for posts)**

- One file per diagram in `components/diagrams/`, named `<Subject>Diagram.tsx` and exporting a component of the same name. Build it from `components/diagrams/parts.tsx`: `Diagram`, `Box`, `Down` and `Loop`.
- Name its parts with `node="…"` so a `<StepThrough>` can highlight them, and list the node names in the file's doc comment.
- Export it from `components/diagrams/index.ts`. That registers it for MDX, and the next `node design-system/scripts/build.mjs` writes its preview page.
- Flows run top to bottom. A left-to-right flow can't hold legible labels at 360px.

## Interactive blocks

Four blocks, all client components, and all usable straight from MDX. Post MDX passes **string attributes and children only**: `next-mdx-remote` strips `prop={…}` expressions from posts (its `blockJS` default), so arrays and objects can't be passed as props.

```mdx
<StepThrough label="Walk the loop">
<VerificationLoopDiagram />
<Step title="The claim" highlight="claim">
The agent says it is done. That is a claim, not a result.
</Step>
<Step title="Run the check" highlight="run check">
Run the real command yourself, this turn.
</Step>
</StepThrough>

<Tabs label="Before and after">
<Tab title="Before">
The report said `all tests pass`.
</Tab>
<Tab title="After">
The report quotes the command and its output.
</Tab>
</Tabs>

<Checklist label="Before you report done">
<Check>I ran the check myself, this turn.</Check>
<Check>I read the output, not a summary of it.</Check>
</Checklist>

<Quiz question="The suite is green. What goes in the report?">
<Choice>Done.</Choice>
<Choice correct>The command, its output, and that it matches the claim.</Choice>
<Answer>
A green suite is evidence only if it ran this turn, against this change.
</Answer>
</Quiz>

<Quiz question="Why keep the log append-only?">
<Answer>
So a restart can rebuild context from what actually happened.
</Answer>
</Quiz>
```

| Block | Props | No JS (feeds, crawlers) | Enhanced |
| --- | --- | --- | --- |
| `StepThrough` > `Step` | `label?` · `Step`: `title`, `highlight?` (space-separated diagram node names) | Every step, numbered, in order, below the diagram | One step at a time. Prev / Next, a numbered step list (`aria-current="step"`), ← → Home End, and a polite live region. The diagram dims every node the step doesn't name |
| `Tabs` > `Tab` | `label?` · `Tab`: `title` | Every panel under its own mono title | A WAI-ARIA tablist with roving tabindex. ← → Home End |
| `Checklist` > `Check` | `label?` | Native checkboxes, which toggle without JS | Adds a live `n of m checked` and Reset. Nothing is stored or sent |
| `Quiz` > `Choice`, `Answer` | `question`, `label?` · `Choice`: bare `correct` on exactly one · `Answer` | Native radios. The answer sits in a native `<details>` | Check marks the pick (`good-text` right, `clay` wrong; announced) and opens the answer. With no `Choice`, it's a "think first" prompt |

**Rules**

1. **Progressive enhancement.** The server HTML holds all the content, so readers with JS off, RSS readers and AI crawlers see every step, panel, item and answer. Hydration only adds controls and hides what's not current.
2. **Keyboard first.** Every control is a native `button`, `input` or `summary`, focus shows the global clay ring, and state changes are announced through a polite live region.
3. **Motion.** Nothing animates except the diagram dim, a 300ms opacity fade that `motion-reduce` turns off. Don't add motion libraries. `<Reveal>` stays the only scroll-motion wrapper, and these blocks don't use it.
4. **Bundle.** No dependencies beyond React. The blocks share `components/interactive/ui.ts` (class strings) and `slots.tsx`.
5. **Ground and text.** Blocks sit on `bg-band`, the one banded ground clay text may sit on. Labels use `text-clay` (eyebrow) or `text-meta` (counters). Body text is `text-soft`. Success is `text-good-text`, never `text-good`. Headings (step titles, questions) are Playfair.
6. **Same claims law as prose.** A quiz answer or a checklist item is public copy. No invented numbers, customers or results.
7. **Children are slots.** `Step`, `Tab`, `Choice` and `Answer` are server components that render a `data-slot` element, which their client parent reads. Don't wrap them in other components, or the parent won't find them.

New block types go in `components/interactive/`, follow the same no-JS-first pattern, get registered in `components/post/mdx-components.ts`, and get a preview entry in `scripts/post-visuals.mjs`.
